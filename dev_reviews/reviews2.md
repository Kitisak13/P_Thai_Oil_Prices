การอัปเดตของทีมงานในรอบนี้ยกระดับโปรเจกต์จากสคริปต์ดึงข้อมูลทั่วไปให้กลายเป็น **Production Data Pipeline** ที่สมบูรณ์มากครับ ทั้งการรองรับ Incremental Sync อัตโนมัติ, การทำ Dynamic Header Detection, การแยกส่งออกทั้ง Wide/Long Format พร้อมรองรับ Parquet รวมถึงการคง Backward Compatibility (`Legacy CSV` และโฟลเดอร์ `Data/`) ไว้ไม่ให้กระทบระบบเดิม

อย่างไรก็ตาม จากการตรวจสอบโค้ดอย่างละเอียด มี **จุดที่ต้องแก้ไข (Bugs / Logic Flaws)** และจุดที่สามารถปรับจูนเล็กน้อยก่อนนำไปรันจริง ดังนี้ครับ:

### 1. จุดที่ต้องแก้ไขใน `main_2.py`

- **[สำคัญ] โค้ดส่วนท้ายไฟล์ซ้ำกัน (Duplicate Code Block):**
- ตั้งแต่บรรทัดที่ `244` ลงไป มีการประกาศฟังก์ชัน `parse_date()`, `main()`, และบล็อก `if __name__ == '__main__':` ซ้ำเป็นรอบที่ 2

- **ผลกระทบ:** เมื่อรัน `python main.py` โปรแกรมจะทำงาน `main()` ซ้ำ 2 รอบติดต่อกันทันที (แม้รอบที่สองจะตรวจเจอว่าข้อมูลอัปเดตถึงวันล่าสุดแล้วและหยุดทำงาน แต่มันจะสร้าง Log ซ้ำซ้อนและไม่ถูกต้องตามโครงสร้างโค้ด)

- **วิธีแก้:** ลบโค้ดส่วนที่ซ้ำตั้งแต่บรรทัดที่ 244 จนจบไฟล์ออก

- **การนับจำนวน `fail_count` รวมวันที่ไม่มีประกาศราคาไปด้วย:**
- ในลูป `for attempt in range(1, max_retries + 1):` หากเซิร์ฟเวอร์ตอบกลับมาปกติ (`HTTP 200`) แต่ไม่มีไฟล์ Excel (เช่น วันหยุดราชการหรือวันที่ไม่มีการปรับราคา) โค้ดจะ `break` ออกจากลูปโดยที่ `downloaded = False`

- ส่งผลให้บรรทัดถัดมา `if not downloaded and not (filepath.exists() ...): fail_count += 1` ทำงาน และนับวันปกติที่ไม่มีไฟล์ว่าเป็นความล้มเหลว (`failed`)

- **วิธีแก้:** แยกตัวแปร `no_data_count` ออกจาก `fail_count` (ซึ่งควรนับเฉพาะกรณี Network/HTTP Error ที่ Retry ครบแล้วยังพัง) เพื่อให้สรุปยอดตอนจบได้ตรงกับความเป็นจริง

- **ควรใช้ Context Manager กับ `requests.Session()`:**
- เปลี่ยนจาก `session = requests.Session()` เป็น `with requests.Session() as session:` เพื่อการันตีการคืนทรัพยากร Connection Pool เสมอเมื่อจบการทำงานหรือเกิด Exception

### 2. จุดที่ต้องระวังใน `combine_data_2.py`

- **[สำคัญ] เงื่อนไขตรวจจับน้ำมันพรีเมียม (`clean_product_name`) กว้างเกินไป:**
- ในบรรทัดที่ `64`:

```python
if any(k in cleaned for k in ('พรีเมียม', 'Premium', 'ี')):

```

การใส่สระ `'ี'` ตัวเดียวโดดๆ ในลิสต์ตรวจจับ Mojibake **อันตรายมาก** เพราะคำว่า **"ดีเซล"** หรือ **"เบนซิน"** (ถ้าสะกดบางรูปแบบ) มีสระ `'ี'` อยู่ด้วย

- **ผลกระทบ:** หากวันไหนในตารางมีแถวเขียนว่า `"ดีเซลหมุนเร็ว"` หรือ `"ดีเซล"` เฉยๆ (โดยไม่มีคำว่า `HSD B7` กำกับ) มันจะติดเงื่อนไข `'ี' in cleaned` แล้วไหลเข้าไปจับคู่กับ `'ดีเซล'` ด้านใน กลายเป็น `'HSD Premium'` ทันที (ข้อมูลดีเซลธรรมดาจะถูกแปลงเป็นดีเซลพรีเมียมผิดประเภท)

- **วิธีแก้:** นำ `'ี'` เดี่ยวๆ ออก หรือระบุลำดับอักขระ Mojibake ที่ยาวขึ้นและเฉพาะเจาะจงกับคำว่าพรีเมียมเท่านั้น

- **การจับคู่ชื่อบริษัท `PT` และ `PTT` ใน `detect_company_columns`:**
- ใน `DETECTION_COMPANIES` มีการจัดลำดับให้ `'PTT'` มาก่อน `'PT'` ซึ่งถูกต้องแล้ว แต่หากในอนาคตมีข้อความอื่นใน Header ที่มีตัวอักษร `pt` ติดกัน (เช่นคำว่า `Option` หรือ `Dept`) คอลัมน์นั้นจะถูกเข้าใจผิดว่าเป็นปั๊ม `PT` ทันที

- **วิธีแก้:** สำหรับชื่อย่อสั้นๆ อย่าง `'PT'` แนะนำให้เช็คด้วย Word Boundary (`re.search(r'\bpt\b', combined_text)`) จะปลอดภัยกว่าการใช้ `in` แบบ Substring ธรรมดาครับ

- **Unused Imports:**
- มีการ `import glob`, `import sys`, และ `from datetime import datetime` ที่หัวไฟล์แต่ไม่ได้เรียกใช้งาน (และ `import sys` ใน `main_2.py` ด้วย) สามารถลบออกเพื่อให้โค้ดสะอาดตามมาตรฐาน PEP8 / Linter ได้เลยครับ
